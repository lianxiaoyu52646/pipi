# 皮皮 V5.10.6 · 单一整合源码工程（可直接用 Android Studio 打包）

## 重要：不要继续覆盖 5.10.1～5.10.5 旧补丁

本 ZIP 是从 V5.10.4 完整工程与 V5.10.5 修复候选补丁合并而成的**独立 Android Studio 工程**。它包含：7本词书、9部已确认安装的英文原著、256分片的 ECDICT、FSRS 及词书防跳动和朗读恢复代码。它**不包含** Piper/Kokoro 巨大模型文件或 sherpa-onnx AAR，因为这些二进制仅在你原本的电脑工程里。

### 直接打包方法

1. **不要删除或覆盖旧工程** `C:\Users\74787\Downloads\9 (2)`；先备份手机学习记录。
2. 将本 ZIP 全部解压至一个**新文件夹**，例如 `C:\Users\74787\Downloads\皮皮V5.10.6`。不要只解压 `app` 子目录；要能在新文件夹看到 `settings.gradle`、`build.gradle`、`app`。
3. 使用 Android Studio 的 Open 打开**新文件夹**，等待 Gradle Sync；新工程会尝试**自动读取旧工程** `C:\Users\74787\Downloads\9 (2)` 下的 AAR、Piper 模型和 Kokoro 模型，并**复制**到新工程（不修改旧工程）。首次同步可能较慢，因为语音资源较大。
4. Build → Make Project 或运行 Gradle `:app:assembleDebug`，APK 位于 `app\build\outputs\apk\debug\app-debug.apk`。**模型缺失会直接停止构建**，而不是制造一个无声的 APK。
5. 建议先运行 `python tools\检查APK语音资源.py app\build\outputs\apk\debug\app-debug.apk`；看到全部通过后，安装升级测试。不要清除应用数据、不要先卸载旧 App。

**如果旧工程不在默认位置**：在新工程的 `gradle.properties` 中增加 `pipiVoiceSource=C:/.../你的旧工程目录`，或在 Gradle 构建命令中加入 `-PpipiVoiceSource=...`。若旧工程中也没有真实模型，必须先恢复原模型资源，单靠本 ZIP 无法使 Piper/Kokoro 发声。

### 本次合并的修复

- 词书：进入即显示英文、音标、中文和「不会」；不再出现多余的顺序模式顶部表单，不按历史词数自动滚动；真正向下滑过且单词离开顶部才累计，退出再进从下一词续学。词书逐批追加单词，降低自动上滑与重绘跳动风险。
- 阅读：撤回 V5.10.4「完整整章预合成才能发声」的高风险改动，恢复尽早合成首句并连续预取播放；文章音频仍需依赖设备上的 Kokoro 模型。**低性能手机仍可能有句间等待，尚未达到无缝朗读的真机验收**。
- 原有 Piper、Kokoro JNI `generate()`（非回调）、阅读设置、护眼模式、备份等代码保留。
- Gradle 新增自动从旧工程**复制**双引擎文件的准备逻辑，以及强制模型存在性校验。若缺少任何关键资源，构建报错，不会静默生成残缺版。

### 两种不同的错误，不要混淆

- **Gradle 直接报“缺少 Piper/Kokoro/AAR”**：旧电脑工程里对应文件不存在或新工程没找到旧目录（见步骤3、5）。
- **能生成 APK，但手机点朗读没声音/提示初始化失败**：请提供实际编译的 `app-debug.apk` 或错误截图；完整的 JNI 和手机性能问题仍需真机诊断。
