# 皮皮 V5.12.23 · 生产级缓存调度与章节索引专项

## 适用版本

**增量补丁只适用于 V5.12.22** 的原有 Android Studio 工程（`app/build.gradle` 为 `versionName '5.12.22'`）。完整源码压缩包用于新建或完整审查工程。请先备份源码与手机学习数据；升级手机 App 时使用原签名覆盖安装，**不可卸载、清除数据或删除缓存**。

## 已实现并入库的改动

1. **按书跳过永久失败片段**：某本书的最后几段进入冷却或人工处理状态时，记录 `book_snooze`，继续处理后面的书。仍未成功生成的片段保持 `ready=0`，全局完成率和书籍完成标记都不会冒充100%。
2. **同书继续后续章节**：若当前章只有失败句段但还有未建立索引的章节，先逐章建立后面的章节再合成，避免失败句段阻塞剩余章节。
3. **全书末尾统一等待或报告**：当所有未完成的书暂时没有可领任务时，按最早冷却时间等待；若只剩永久失败段，报告人工处理而非发布“全部完成”。手动重新点击“开始”后可以再次尝试这些隔离段。
4. **559章预处理**：新建 `app/src/main/assets/voice-library/chapter-manifest.json` 和 `voice-library/chapters/<id>/<001..>.json`，保持原书文本和句段顺序完全一致。每章运行时只解析该章的 JSON，不再重新解析整本书或计算整本书 SHA-256。
5. **检测同数量内容变更**：通过构建时验证的逐书 SHA-256，启动时核对所有已索引及已完成书籍。若有内容变化，即使段数没变，也仅重建受影响书籍的 SQLite 索引，保留其他书已完成标记和所有已有 PCM 文件。
6. **升级保护**：新增辅助 `book_snooze` 表采用 `CREATE TABLE IF NOT EXISTS`，现有按音色/语速的数据库名、`segments` 表、哈希键及音频格式均不变；`onUpgrade()` 改为拒绝未知迁移而不直接 DROP 旧数据。
7. **索引完整性兜底**：不再以“没有未完成行”直接判定一本书完成；会核对该书所需的完整 seq 行数，若索引行丢失仅重建这一书索引，并在导入章节时重新识别已有 PCM。
8. **构建保护**：Gradle `preBuild` 增加 `verifyVoiceChapterAssets`，在打 APK 前检查全部20本原始文本 SHA、559个分章资产 SHA 和每章位置，防止新旧索引混用；GitHub CI 也增加逐章文件验证。

### 缓存升级兼容

- **保留不变**：SQLite 文件名、`segments`、`failures`、`book_tasks` 数据和所有 PCM 真实音频文件。
- **新建**：`book_snooze` 辅助表、章节清单与分章 JSON 资产。
- V5.12.22 的 `bookwise_v2` 全局签名不变，若书籍布局和 SHA 一致，直接接管已完成进度。
- 新音色与旧音色仍然是不同缓存档案。继续时请保留原音色与语速。
- *迁移索引 ≠ 删除音频*。重建受影响的索引时，已有音频由原哈希键重新识别，速度和成功率仍依赖手机资源。
