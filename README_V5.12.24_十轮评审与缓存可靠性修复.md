# 皮皮 V5.12.24：十项审查迭代与缓存可靠性专项

基线：V5.12.23；增量补丁仅供 V5.12.23 工程覆盖。完整源码含20本原著和 559 章节离线资源，但**不包含大型 Kokoro/Piper ONNX 模型及原项目的 sherpa-onnx AAR**，构建时仍需原本地语音依赖。

## 十轮审查与修改记录

1. **旧任务索引复用检查**：发现单凭相同的书籍数量与清单签名可复用旧队列；增强按书籍 ID、片段序号区间和章节数验证布局。测试：清单/旧索引检查通过。
2. **迁移中断恢复**：原流程可能先更新全局清单签名再对齐书籍签名；调整为先对齐、后更新签名，避免异常暂停后误认为已迁移。测试：源码路径验证通过。
3. **重建后 PCM 扫描标记**：删除部分索引时，旧的 files_seen 标记可能仍保留；在内容变更、缺行修复、书籍索引失效时删除扫描标记。测试：三条索引失效路径验证通过。
4. **零进度扫描**：原扫描逻辑只比较文件数量，文件数量未变时可能直接跳过；done=0 时不再信任仅凭文件数得到的旧扫描标记。测试：零进度保护检查通过。*注意：普通逐章索引本来就在按哈希识别已有 PCM；此修改保护特殊恢复路径。*
5. **完成状态安全**：一书只有索引齐全，且 ready=1 的行数等于总行数时才认定完成。测试：不完整 SQLite 行数模拟通过。
6. **异常计数保护**：PCM 缺失后回滚完成数，不允许 done 计数变为负数。测试：SQLite 负数保护模拟通过。
7. **音频原子写盘**：为每次生成使用独立临时文件，写入后执行文件同步，再安装正式 PCM 与校验信息；异常时清理临时文件。测试：Kotlin 真正文件写读和临时文件检查通过。
8. **校验文件竞态**：先清理可能过期的 SHA 校验文件，再发布新 PCM，避免新 PCM 与旧 SHA 短暂错配而被误删。测试：独立音频写读及损坏恢复检查通过。
9. **容量与重复内容**：新片段写入之前同时预留系统空间和预计本段 PCM 大小；相同且有效的音频直接复用。测试：PCM 重复写不覆盖已有音频、代码检查通过。
10. **全业务回归**：复查 FSRS 收录、词典、Android 生命周期、版本号一致性、20本原著资源；执行37项现有 JS 回归、旧队列模拟、Kotlin 索引接口和 PCM 读写测试，全部通过。

## 安装

1. 备份原 `C:\Users\74787\Downloads\pipi` 工程；在App内部导出学习记录JSON（原音频PCM文件不包含在学习JSON里）。
2. 若本地是 V5.12.23，则使用 `皮皮_V5.12.24_十轮评审可靠性修复_增量补丁_适用V5.12.23.zip`，解压到项目根目录，按相对路径覆盖。
3. Android Studio 执行 `:app:assembleDebug`（需要原 Kokoro/Piper 模型及 sherpa AAR）。
4. 用与旧 App 相同的签名覆盖安装，**不要卸载、不要清除数据、不要删除已有 PCM/SQLite**。
5. 先核对旧音色和缓存进度，再安排至少一整夜缓存测试。

## 明确限制

- 没有在本次环境内完成完整 Android SDK Gradle 构建，也没做小米真机连续24～72小时测试。
- 测试脚本对 SQLite 行为有模拟校验，但模拟**不等于**真机数据库迁移验证。
- 此版没有把 WebView 整份 JSON 保存完全改造成增量业务 API；也无法绕过 Android 的后台服务启动或强行停止限制。
- 原音色缓存与不同音色、语速的缓存仍是相互独立的，恢复时必须核对对应档案。
