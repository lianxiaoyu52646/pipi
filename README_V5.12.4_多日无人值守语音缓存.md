# 皮皮 V5.12.4｜连续多日无人值守缓存增强（基于 V5.12.3）

## 这次解决什么

用户点击一次「开始缓存」后，目标是持续生成九本已内置原著的离线 Kokoro 语音。正常锁屏、切换页面、读写短时异常无需用户点「暂停」再点「开始」。已完成语音文件保留，服务重建后重新校验实际文件并续接。**不承诺每个安卓品牌／系统都能绝对不断电、不限后台或绝对自动拉起**。

## 核心代码改动

1. **独立缓存进程**：AndroidManifest 将 `LibraryVoiceCacheService` 放入 `:voice_cache`，Kokoro JNI 仅在该进程生成。即使原生推理函数无法被 Kotlin 线程取消，回收该独立进程也不必杀掉主 UI 进程。
2. **真正的卡死看门狗**：监测模型初始化、JNI 合成、文件写入以及整段生成／扫描停滞。超过约 12 分钟无真实工作（扫描容忍 15 分钟）时记录原因、保存任务意图、安排恢复检查，并重启独立进程；非正常线程退出同样设置恢复检查。
3. **持久化用户任务意图 + 心跳**：跨进程 `AtomicFile` 分开保存是否要继续、音色／语速和服务真实状态。Android `START_STICKY` 重建可读回此前任务。`AlarmManager.setAndAllowWhileIdle` 提供低功耗环境的兜底检查，后台拉起仍受 Android 12+ FGS 限制。
4. **真实进度重新扫描**：重启后先校验磁盘上的 PCM 缓存，再合成缺失文件。考虑全书中重复出现的句子，解决计数不准确和进度假到 100% 的风险。
5. **写盘后校验**：PCM 使用与以前相同的文件名、SHA-256 key、v2 PCM 格式；每个新文件写入后校验成功才计入完成量。断点无需重新合成已验证文件。
6. **资源异常自动等待**：正常合成／写盘失败自动重试；设备内存短缺、存储空间不足按较长间隔等待；配置／模型缺失保留任务并提示需要修复安装资源，绝不伪造完成状态。
7. **性能方向**：长句拆成不超过 220 字符的多个原生调用再合成一个兼容 PCM 缓存文件；PCM 批量写入替代逐个 `writeShort`；线程数按 CPU 核数在 2～4 之间选择。**尚无真机性能实测，不保证速度提升百分比**。
8. **缓存页透明**：展示本次新生成片段数、新增 MB 和平均每小时片段数；超过五分钟没有真实进度时停止误导性动画。自动恢复期间仍可手动选择暂停。

## Android 特别说明

- `START_STICKY` 恢复由系统调度；厂商强力后台限制或用户强制停止后，不存在可保证的自动拉起机制。
- Android 12 及更新版本限制后台直接启动前台服务；恢复闹钟属于**兜底尝试**，调用可能被系统拒绝，新版会记录后继续尝试，而不是把它宣称为绝对可靠。
- 长时间全书语音缓存消耗 CPU、电量和大量储存空间。建议充电、散热良好、关闭皮皮的系统电池后台限制，并为生成文件预留足够空间。空间不足时不会伪装生成。
- 若主 APK 缺 Kokoro 模型或第十本原著，代码无法凭空补齐。该基线的真实索引为 **9本、42,264 个句段**；《汤姆·索亚历险记》完整原文仍缺失。

## 如何使用

**只要手中原工程是 V5.12.3**：先备份原工程，然后将 V5.12.4 增量补丁内容解压到原工程根目录，按目录覆盖对应源码；在 Android Studio 重新编译 APK，使用相同 applicationId／签名覆盖安装，不卸载旧 App。已有已生成的缓存存于 App 私有存储，**源码覆盖不会删除它们**。

**如果不是 V5.12.3**：用完整源码包建工程，编译时从你的旧 Android Studio 工程导入 Piper/Kokoro 模型与 sherpa-onnx AAR。不要以为这 37MB 源码包已经包含几百 MB 的模型。

## 验收建议（必须真机）

1. 点击缓存后，锁屏持续 12～24 小时，观察前台服务通知，以及本次真实写入的 MB 和片段数是否持续增长。短时间长句或设备过热可造成暂时停顿，但不会被误当成功。
2. 可通过开发测试模拟单独回收 `:voice_cache` 进程，确认系统前台服务／闹钟恢复后不清零已有 PCM。**不要点「强行停止」**模拟普通回收，强行停止会改变系统恢复策略。
3. 至少做 72 小时充电、散热、存储余量充足条件下的测试，对照每隔几小时真实文件数和可用空间，确认没有长期只有动画、没有文件的情况。
4. 逐步使用接近耗尽的磁盘空间、阅读器模型占用、大段文本等异常条件，核验不会错误显示已完成，也不会删除过去缓存。
