# 皮皮 V5.12.9：P1/P2 维护与可靠性增强版

## 基线与版本
- 仅适用于 **V5.12.8** 源码项目；完整工程含20本原著和7套词书。
- versionName 5.12.9，versionCode 38。使用原来的 applicationId 与签名覆盖安装，勿卸载旧 App。
- 新源码包不重新分发本机大型 Piper/Kokoro 模型及 sherpa-onnx AAR，构建时仍需从旧工程安全导入。

## P1 修复
1. 词书滚动：保持“用户确实向上滑出屏幕=会了，不入 FSRS”的规则。移除已经确实滑过的旧行，并使用精确像素高度的占位块保留滚动坐标；DOM 节点控制在较小范围。用户未滑过的行不回收。
2. 最后几词：追加一个仅在词书真正末尾出现的滚动尾部空间，允许最后一行完全滑过屏幕顶部，进度能到100%。
3. 学习记录：Android 端使用 SQLite **优先提交的主副本**；WebView 的 localStorage 和 IndexedDB 仍保留为兼容镜像及快照，便于原著页面、JSON 备份和旧版升级。每次保存增加递增版本号，重启优先选取校验通过且版本较新的记录。**SQLite 目前存整份学习 JSON，不是已完全规范化的逐字段表结构**。
4. 阅读书签：SQLite 独立保存原著阅读进度，老版 localStorage 书签会被安全导入；继续同步旧格式以兼容备份/恢复。
5. 已缓存语音：阅读优先直接读取已有 PCM 文件；遇到尚未缓存的语音才加载 Kokoro。若后台全书缓存正在运行，阅读只播放已有 PCM，不抢模型、不擅自暂停用户缓存任务；遇到未缓存片段会明确提示。
6. 全书索引：首次建立、原著目录变化时，SQLite 每1000句持久提交一次，崩溃后保留已提交的队列及检查进度。正常恢复仍直接复用已建索引，无需全量检查音频。
7. 音频校验：新生成 PCM 写盘后添加 SHA-256 附属校验文件；正常断点查询仍按文件头/大小快速判断，实际朗读和全部完成前的终检使用 SHA-256 检查音频内容。旧版PCM文件继续兼容；旧文件在首次深度终检时补建校验值。

## P2 修复
1. 改词书但词数不变：依据整个词书的英文/释义/例句签名识别变化；如内容确实变化，重置这本词书的滑动浏览位置。**不自动删除 FSRS、生词本历史，以防误删用户学习记录**。
2. 清空学习记录：二次确认后同时清理 SQLite 的学习主记录、原著书签、WebView 学习键及 IndexedDB 自动快照。不会清除原著正文与已生成的音频，避免重新下载或重算。

## 数据安全与升级提醒
- 升级前从「工具 → 学习数据备份」导出 JSON，并备份 Android Studio 工程。
- 增量包必须解压到 **V5.12.8 项目根目录**，保留 ZIP 内路径并允许覆盖同名源码。
- 使用**相同应用签名**编译后覆盖安装，不能卸载、清除 App 数据。
- 既有音频仍是原版 PCM v2 格式，旧缓存可复用。
- 如果已经缓存了大量语音，首次终检的 SHA-256 深度校验比原来慢；普通中途恢复不会逐个重算哈希。
- 原来的 P0 无人值守恢复机制予以保留，但 **没有完成72小时 Android 真机测试**，不能承诺所有品牌手机百分百连续运行。

## 验收建议（必须真机验证）
1. 升级前记录词书滑动位置、生词本数量、FSRS 今日到期数、某本原著当前书签，升级后逐项对照。
2. 选千词以上词书，连续滑动上千词，确认没有越来越卡；最后几个词可滑出并显示完成。
3. 未点击「不会」的词不入生词本，阅读点「不会」会进入同一本。
4. 全书缓存不中断时点击已缓存章节可直接读；未缓存章节要提示，不可暂停背景任务。
5. 断电模拟 / 进程恢复后检查 SQLite 保存的进度和已生成的音频，不能只看动画。
6. 导入同词数不同释义的词书，只重置对应浏览位置；已收录生词记录保留。
7. 测试清空数据时先备份，清空后重启不可又从 SQLite/旧快照恢复出旧数据。

## 未完成的验收
- 当前环境缺少 Android SDK 和你的完整本地模型/AAR，不能执行真实 Gradle APK 编译；需在你的 Android Studio 构建并真机安装。
- 自动化测试覆盖源码层与部分本地 PCM 算法，未覆盖不同安卓品牌连续72小时运行、全部80,000多段合成或低内存冲突场景。
- SQLite 主记录采用一行 JSON，后续若数据规模远超现有安全上限仍可能需要更细颗粒的表结构迁移；本轮先确保安全兼容。
