# 皮皮 V5.12.21 · 跨天语音缓存恢复与诊断增强

**升级基线：V5.12.20。** 本次修改针对小米手机出现的：累计约 8,005/82,926（9.65%）、近26段纯合成平均约15秒、累计77段/小时、恢复8次，日志周期性报“用户或系统停止”。有真实产出，但 Android 多次终止了后台缓存进程；不能把这些退出全归咎于 Kokoro 合成卡死。

## 具体修改
1. Android 进程退出诊断：明确区分 `REASON_USER_REQUESTED`、原生崩溃、ANR 等，并展示系统返回的退出描述。该原因只能表明用户/系统请求终止，无法据此断定是手机杀后台还是用户手动停止；不伪装成合成卡死。
2. 恢复闹钟被后台启动限制拦截时：持久化失败事件（包含发生时间和异常类型），缓存详情页能在缓存进程已经停止时读出这条记录；尝试发布通知提醒用户打开 App 继续（需通知权限且应用未被系统真正强行停止）。
3. 进入 App 后：检查后台缓存进程退出是否晚于最后心跳，必要时及时请求启动缓存服务；同时重新安排可能被系统取消的恢复闹钟。后台被 Android 限制时不能强制绕过系统策略。
4. 系统电池限制诊断：状态页显示后台受限、系统电池优化等信息，提供一键打开**皮皮应用详情设置**入口，由用户手动设置“电池无限制/允许后台、自启动”（不同小米系统文案可能不同）。代码不会擅自修改系统权限。
5. 修复UI停滞误判：5分钟无产出时显示“正在诊断”，而不是声称“正在自动恢复”。12分钟看门狗仍由原生服务独立判断；在已确认最近2分钟内成功写盘以前，不会报告真实持续生成。
6. 将紧邻同一进程退出的 `restart`/`process_exit` 两条重复日志合并显示；缓存退出历史读取增加30秒节流，避免页面轮询频繁查询系统进程历史。
7. 升级版本到 `5.12.21`、`versionCode 50`；保留现有 PCM 文件格式、Kokoro 音色档案、SQLite 数据库、断点索引、失败片段隔离和20本离线原著。

## 不能保证的事情
- Android / 小米的**强制停止、任务管理器停止应用、厂商深度省电**可能同时取消闹钟和后台运行权限；普通第三方 App **无法**保证在这种情况下无条件自动重启。此时必须打开一次 App 或点允许的通知后恢复；旧缓存不会因此自动删除。
- `START_STICKY` 和 `setAndAllowWhileIdle` 是尽力恢复，不能保证在特定分钟启动。
- 本次源代码没有接入用户手机，不知道用户手机实际退出的完整系统诊断描述，因此不能把“用户或系统停止”的真正根因说死。

## 使用方法
1. **不卸载旧 App、不清除数据、不要删除PCM文件或SQLite数据库。** 备份本地工程，最好再导出学习记录。
2. 将 `V5.12.21` 增量补丁**解压到 `C:\Users\74787\Downloads\pipi` 项目根目录**，按 `app/...` 等相对路径覆盖旧文件。
3. Android Studio 编译 `:app:assembleDebug`，使用之前相同签名覆盖安装 APK。
4. 进入“全部原著语音缓存”核对已完成片段总数和之前相同的音色、语速；如果页面提示后台限制，点“打开皮皮系统设置”，手动调整电池和后台运行策略。
5. 从锁屏前后各记录一次 `累计完成`、`本次真实新生成`、`恢复次数`、`最后写盘时间`。至少做一次8至12小时测试和后续跨天测试。
