# 皮皮 V5.10.7｜英文阅读连续朗读优化

## 本次与 V5.10.6 的差别

1. **真正按声音长度预缓冲，而非按 2～3 句话**：以前 2～3 个短句可能不足 2 秒，几段后容易断粮。新版测量已经生成的真实 PCM 音频时长及合成耗时，根据设备速度动态调整首次开播所需的缓冲量，目标约 12～55 秒音频。首次准备最多约 90 秒（模型加载首句也可能额外耗时）。
2. **持续提前生成，缓冲区改按音频时长控制**：最多保留约 90 秒待播声音，避免某些长句占满“按句数计”的小队列，也避免无上限占用内存。PCM 写入音频设备时使用 ShortArray，减少反复转换开销。
3. **离线 PCM 磁盘缓存**：同一句文字、同音色、同语速的语音合成完成后保存在 app 私有缓存目录；退出重进可以复用，缓存容量自动控制在约 144MB 以内。系统清理缓存后会自动重新合成；坏缓存自动丢弃。
4. **显示真实播放状态**：顶部朗读按钮在缓冲时显示“⏳ 准备”，真正开始有声播放时显示“⏸ 暂停”，缓冲不足时再次提示，不再让用户误以为模型加载失败。
5. **暂停时停止继续抢占合成 CPU**：用户暂停文章或点词由 Piper 发音时，后续 Kokoro 合成也暂停（已执行中的一次生成需要完成才能中断）。Piper 模型与配置没有变。
6. **修复旧会话阻塞新播放**：取消播放后，旧会话不再长期阻塞播放线程的下一次启动。

## 如何在 Android Studio 使用（不要叠加旧补丁）

- 下载 V5.10.7 完整独立工程 ZIP，解压到一个全新文件夹，例如 `C:\Users\74787\Downloads\皮皮V5.10.7`。
- **原 `C:\Users\74787\Downloads\9 (2)` 工程必须保留**，里面需要完整的 `app/src/main/assets/tts` 双模型和 `app/libs/sherpa-onnx-1.13.8.aar`。
- Android Studio 打开新工程；Gradle 同步时会尝试从原工程自动复制缺失的模型和 AAR，构建前会检查必要资源。
- 执行 `:app:assembleDebug`，输出 APK：`app/build/outputs/apk/debug/app-debug.apk`。
- 安装升级前先从旧 App 导出学习备份，不要卸载旧 App；若同一电脑、同一 debug 签名通常可直接覆盖安装。
- 如原模型路径不同：在新工程根目录的 `gradle.properties` 中加入 `pipiVoiceSource=C:/你的旧工程路径`，或使用 `-PpipiVoiceSource=...`。

## 用户可感知的代价和局限

- 为了减少中途卡住，**第一次开始朗读会比旧版多等一段音频缓冲时间**；手机越慢，可能等得越久。上限设置是为了避免无限准备。
- 若设备的 Kokoro 合成速度 **持续慢于实际朗读速度**，任何有限缓冲最终都会耗尽。此次只大幅降低突发断流概率，不保证每台手机听完整本书完全零中断。
- 重新听以前已合成的句子可以通过本机 PCM 缓存显著加快准备；缓存由系统管理，会受空间及清理影响。
- 仍然只含 9 本已校验的原著，第10本《汤姆·索亚历险记》未补齐，正式 release 检查会阻止发布；Debug 用于测试。

## 手机上最重要的验收流程

1. 打开原著，按朗读按钮，观察“准备”提示，等待开始播放。
2. 从未缓存的章节连续听 10 分钟，特别关注第 2～5 分钟是否再出现明显无声等待。
3. 暂停、继续、点词发音，再继续文章，观察是否能恢复。
4. 关闭并重新打开同一章节，观察重复部分是否明显更快开始发声。
5. 若仍出现停顿，记录**手机型号、开始播放到停顿的大致时间、停顿长度**。这样的信息才能判断是设备合成速度的硬限制还是新问题。

注意：这是一个**经过离线源码及浏览器测试的 Android Studio 工程候选版**，不应描述成已通过真实设备验收的“绝对流畅最终版”。
