# 皮皮 V5.12.16 · 整书语音缓存稳定性增强

## 更新范围
以 V5.12.15 完整源码为基线。本次只改后台缓存稳定性与诊断，不改变 FSRS、词书、20本原著、原来的 SQLite 缓存队列及 `pipi-kokoro-library-v1` PCM 音频目录，也不改变原有音频哈希、声线、语速与文件格式。

1. **跨进程模型互斥**：新增 `KokoroProcessGate.kt`，在阅读器进程和 `:voice_cache` 进程之间使用 OS 文件锁防止同时加载 Kokoro。OS 随进程退出自动释放锁。已有缓存 PCM 可直接播放；在后台缓存占用模型时朗读未缓存句子可能提示暂停后台缓存，而非同时起两个重模型。
2. **失败句段隔离重试**：在旧版 SQLite 队列增设 `failures` 表（无须重建旧队列），对抛出合成异常的片段单独记录失败次数、错误与下一次重试时间；其他片段先继续，重试后才最终完成。不会将失败片段假标已完成。
3. **原生死锁隔离**：看门狗主动结束独立进程前，把卡住的句段 Hash 写到持久化失败队列；下次恢复可先处理后续句段。Android 30+ 尽力使用 `ApplicationExitInfo` 识别内存回收、原生崩溃、ANR；系统未返回可靠理由时不会凭空判定原因。
4. **真实性能诊断**：新增模型加载耗时、近50段纯合成用时、实时系数（合成耗时/音频时长）、单片段写盘耗时与 SQLite 完成事务耗时；首页仍保留累计平均速度。
5. **诊断日志面板**：缓存页面可展开最近8条故障/恢复记录，日志文件最多保留32条；移除误导性“本阶段已等待xx秒”的表述，改为阶段持续时间。
6. **现有缓存保护**：不修改 `NarrationAudioCache` 的 PCM v2 格式、不清理旧文件和缓存数据库、不改变语音资源打包。失败记录为独立辅助表，成功后自动移除。

## 注意
- 这版不保证101段/小时必然加速，重点是避免反复卡住同一句、揭示瓶颈。具体提速需要在相同小米真机与温度下对比性能统计。
- 模型已在阅读器占用时，后台缓存会等待释放；后台缓存运行时，阅读器可播放已经缓存的片段，未缓存片段需要先暂停缓存，避免同时加载双模型。
- **不要卸载旧版 App、不要清除应用数据**；保留原签名覆盖安装才能继承 SQLite 和 PCM 缓存。
- 安卓系统可能限制后台前台服务重启，不可保证进程被系统强制停止后立即恢复。
