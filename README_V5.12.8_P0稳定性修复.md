# 皮皮 V5.12.8 — P0 优先稳定性修复

基于 V5.12.7 20本原著完整工程。

## 本轮实装
- Native 学习记录 SQLite 安全副本：`StudyStateStore.java` 使用 SQLite 事务和 SHA-256 校验；`MainActivity.Bridge` 提供写入/读取接口。所有正常学习保存现在双写 localStorage、SQLite，并保留 IndexedDB 快照。首次运行不删除旧记录；没有 localStorage 且本机已有校验通过的 SQLite 副本时尝试恢复。恢复备份后同步 SQLite 安全副本。
- 缓存看门狗：分开判断前台服务心跳与真实音频写入；当合成过程长时间无新写入且无模型活动时，通过状态文本标示风险，而不是只依赖 CSS 动画。
- Kokoro 卡死独立进程重启前先持久化重启原因及次数；重启时避免把同一次恢复重复计数。
- 继承 V5.12.7 SQLite 音频任务队列、自动恢复闹钟、已生成 PCM 文件复用和 20 本原著。

## 不能过度承诺的部分
- **学习数据属于安全双写阶段，而不是完全 SQLite 单存储**：localStorage 仍是现有页面同步读写的主渠道，SQLite 作为校验副本和救援渠道。彻底切换 SQLite 唯一主存储需处理备份回滚及多 WebView 页面事务。
- **尚未验证72小时无人值守真机运行**，不能保证任何安卓系统或手机厂商的后台限制都可绕过；底层 Kokoro 原生模型故障及持续低空间仍可能影响任务。
- 没有提供本环境真实 SDK + 大型模型的 APK 编译结论；需要在 Windows Android Studio 本机执行完整构建。

## 更新
V5.12.7 项目根目录直接覆盖增量包内 `app/` 对应文件，重新使用相同签名构建 APK 并覆盖安装。**不要卸载旧 App 或清空数据。** 首次升级先在“工具→学习数据备份”导出一份 JSON。

## 真机验收
1. 打开学习页，背5个词并标记一个“不会”；进入后台再启动确认进度保留。
2. 停止后台缓存服务模拟系统回收，检查自动恢复原因和真实音频完成数。
3. 在本机验证连续24～72小时逐小时文件增长；误触暂停时必须完全停止。
4. 导出学习数据、从备份恢复后验证 localStorage 与 SQLite 镜像一致。
