# 皮皮 V5.10.9：工具 → 一键缓存全部原著语音（测试版）

## 本次明确实现

- 在「我的学习 → 有声书工具」增加「一键缓存全部原著语音」，打开专用工具页面。
- 自动按**现有9本真实原著**、按章节、按阅读器原句列表依次生成 Kokoro PCM16 音频；共 **42,264** 个原句/长句片段。
- 页面显示全部进度百分比、已完成句数、当前书名/章节；Android 前台服务通知栏同步显示。
- Android 原生 Foreground Service (specialUse) + Partial WakeLock，锁屏、离开阅读页面之后仍能继续工作（具体运行时间仍受系统省电/厂商限制）。
- 任务暂停/继续、重启后重扫并跳过已生成音频；支持删除所有语音缓存。系统/用户强制结束应用后，需要重新打开工具按「继续」。
- 缓存在 app 内部持久目录 `filesDir/pipi-kokoro-library-v1`，与文章播放器**共用** `NarrationAudioCache` 的 PCM 格式、模型/声线/语速/文本 SHA256 key，生成完成的相同语音无需实时重复合成。
- 前台文章朗读和后台缓存经过同一个 Kokoro 模型使用锁，防止同时加载两个巨大的 ONNX 模型。
- 文件头损坏后自动再生成；手机存储空间不足时暂停并报错（预留约256MB）。
- 已含 `NarrationBufferPolicy.kt` 和全部新增的 Kotlin 源文件，避免旧补丁缺失依赖的编译问题。

## 用户操作（无需叠加旧补丁）

1. 建议**先备份学习数据**，保留现有项目。
2. 解压本 ZIP 到一个**新文件夹**（例如 `C:\Users\74787\Downloads\Pipi_V5.10.9`），用 Android Studio 打开该文件夹。
3. 新工程尝试自动从 `C:\Users\74787\Downloads\9 (2)` 导入 Piper/Kokoro 模型及 `sherpa-onnx-1.13.8.aar`。如果 9 (2) 没有 AAR，还会尝试 `Downloads\3`。必要时可以在 Gradle 命令加 `-PpipiVoiceSource=你的旧工程路径`。
4. Gradle 执行 `:app:assembleDebug`。生成 APK 位于 `<新工程>\app\build\outputs\apk\debug\app-debug.apk`。
5. 安装后到「**我的学习 → 有声书工具 → 一键缓存全部原著语音**」。选择 Sarah (推荐) 1.0×，点击开始缓存；允许通知权限并确保电池策略允许后台活动。锁屏后可从通知栏查看进度、暂停/继续。
6. 缓存完成或部分完成后，在阅读页选择**同样的声音和语速**，即可命中已生成的缓存。不同音色或倍速生成的音频不能通用。

## 重要说明

- **现有资源只有9本全文，《汤姆·索亚历险记》仍缺失，不能缓存缺失的第10本。**
- 全书 PCM 音频占用空间**可能达到数 GB、甚至更多**。此版本采用音质无损 PCM 方便即刻与播放器共享，尚未增加压缩编码，不适合手机空间不足时全部生成。请考虑只保留有足够空闲空间的设备，或未来升级压缩格式。
- 首次预生成需要很长时间，可能是几小时乃至更久，并且耗电、发热。建议接上充电器并注意散热，避免覆盖手机或放在枕头下。
- 后台前台服务与唤醒锁能显著降低锁屏被挂起的概率，**无法绕过所有 Android 厂商的省电/后台策略**。系统杀死进程后不会自动偷偷重启，用户回到工具页点击“继续”即可扫描已生成文件继续。
- 用户手动启动阅读朗读时，后台缓存会暂停以释放 Kokoro 模型，避免内存资源冲突。
- 本 ZIP **不包含**私有语音模型和 AAR，沿用用户电脑已有资源。若自动导入失败，Gradle 应阻止创建不完整的 APK。
- 已完成 JS 静态/真实浏览器模拟界面、Kotlin JVM 音频缓存测试、Android API **接口桩编译**以及缓存资源一致性检查。**没有在真实 Android SDK+完整 sherpa 模型环境编译 APK，也没有真实锁屏数小时运行验收。** 本工程为待真机验收的测试版本，不承诺用户手机已验证。
