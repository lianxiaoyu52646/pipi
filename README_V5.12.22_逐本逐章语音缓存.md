# 皮皮 V5.12.22 · 逐本／逐章离线语音缓存

基于 V5.12.21 源码。**本版本将英语原著的 Kokoro 音频预生成改为按书、按章管理，并不是将书籍内容翻译成中文。** 20本原著合计82,926段，保持原文本、模型和 PCM 格式不变。

## 本次真实改动

1. `VoiceCacheIndex.kt`：沿用原来按音色/语速分库的 SQLite 数据库文件，新增 `book_tasks` 辅助表。旧 V1 全量队列的完整签名与实际书籍匹配时，一次性采用已有 `segments.ready`、已完成数量和失败隔离记录，不重新生成 PCM。
2. 无法复用旧索引或从零缓存时，仅导入当前书的当前章。每章导入的片段、章节游标和已完成数在同一个 SQLite 事务中提交；中断后不会跳过未提交章节。
3. `LibraryVoiceCacheService.kt`：先完成当前书的章节，再自动进入下一本；未完成/冷却/长期失败片段不能把本书标成完成；所有20本完成后仍执行磁盘完整性终检。
4. 不改变文件哈希键、PCM 布局、Kokoro/Piper 模型、音色缓存档案、SQLite 文件名、FSRS 和复习数据。
5. `voice-cache.html`：新增“已完成多少本／当前书完成比例”展示，整体82,926段进度仍是跨书累计。

## 安全升级（重要）

- 增量补丁适用于 **V5.12.21** 工程，解压后覆盖同名文件，项目根目录不应多出一级 `Pipi_*` 文件夹。
- 提前备份 V5.12.21 工程和学习数据；使用**同包名、同签名**覆盖安装，不要卸载旧版、不要清除 App 数据、不要点击“删除缓存”。
- 旧 V1 SQLite 内容签名与新内置原著完全一致时，原有进度直接沿用；否则仅重建数据库索引，已生成 PCM 不删除，并在处理对应章节时逐批重新识别。
- 从原音色与语速继续，切换音色/语速仍然是独立的缓存档案。
- 构建：在 Windows 项目根目录运行 `./gradlew.bat :app:assembleDebug`（PowerShell 使用 `.\gradlew.bat :app:assembleDebug`）。
