# 皮皮 PIPI V5.12.1 | 后台语音缓存不中断修复

修复基线：V5.12.0（以 V5.11.1 完整版升级的 V5.12.0）；APK 包名保持 `com.sprint7.offline`，版本号 `5.12.1` / `versionCode 30`。

## 原因：源码证据

1. 旧 `MainActivity.java` 的 `Bridge.speakArticle()` 每次原著朗读**主动发送 `ACTION_PAUSE` 给后台缓存服务**，这不是用户主动暂停；是确切可复现的业务逻辑错误。
2. 旧 `LibraryVoiceCacheService.kt` 的前台服务返回 `START_NOT_STICKY`，系统重建服务不会自动恢复；状态页面还把意外中断直接展示为 `paused`，容易误认为用户按了暂停。
3. 旧代码的储存空间不足及临时合成/IO异常会直接结束任务；旧的 `ACTION_CLEAR` 在缓存中尝试删除时也会隐式请求暂停。
4. Android 仍可能由于厂商后台限制、过热、系统资源不足或用户强行结束而中断进程。应用无法对所有设备保证绝不中断。

## 本次实际修改

- **缓存优先**：文章朗读请求不再调用 `ACTION_PAUSE`。后台缓存活跃时，阅读页面收到说明提示（允许阅读文字和 Piper 单词发音），需用户**自己**暂停后才能启动另一套 Kokoro 实时原著朗读，避免两份大模型同时运行导致内存崩溃。
- **持续意图持久化**：用户点“开始”后，记录 `user_wants_continuous_cache=true` 和音色、语速，只有手动按暂停/自然完成/无法自动恢复的致命错误才清除此意图；即使 Android 重建服务，也可按原选项继续。
- **异常中断恢复**：正常运行的前台服务使用 `START_STICKY`，接受 `null Intent` 和 `ACTION_RESTORE` 自动恢复；App 回到前台时，若存在未完成任务且服务未在运行，会再尝试续接。
- **缓存断点续接**：保持原有 PCM 文件路径与文件名规则；重启重新扫描有效片段，跳过已完成语音，不重新生成、不删除学习数据。
- **空间不足改为等待**：低于保留阈值时持续显示“等待空间”，释放唤醒锁并定期检查；空间恢复后自动继续，而不是将状态伪装为手动暂停。
- **瞬态合成异常自动重试**：保留已生成文件，按5秒起、最长120秒的退避间隔自动重试，期间显示重试原因；可响应用户主动暂停。JNI加载/资源缺失等致命问题，以及连续3次 OOM，会明确报错，不会无限占用内存。
- **用户手动暂停仍有效**：通知栏/页面两处暂停均取消自动恢复意图；等待 Kokoro 模型锁时也可以在1秒内响应暂停，正在合成的长句需要完成当前合成调用后才停。
- **删除不再误暂停**：缓存运行期间尝试清理只提示先手动暂停，不暗中触发暂停。
- **状态解释**：增加恢复中、磁盘等待、重试中、正在响应暂停等状态文案。
- **可排查日志**：`adb logcat -s PipiVoiceCache` 可查看启动、手动暂停、自动恢复和重试原因。

## 如何更新

**推荐**：你已有完整 V5.12.0 工程，则下载 `Pipi_V5.12.1_ContinuousVoiceCache_Patch_From_V5.12.0.zip`，先复制工程作备份，再把补丁里的文件按相对路径覆盖原工程；用 Android Studio 重新编译 `:app:assembleDebug`。请不要把 ZIP 直接塞进 `app` 文件夹，需对齐 ZIP 的最外层项目根目录。

如不知道项目是否已经完整更新到 V5.12.0，下载 `Pipi_V5.12.1_AndroidStudio_Source.zip` 更稳妥，解压后用 Android Studio 打开工程，并使用原工程已有的 Piper/Kokoro 模型与 AAR 构建（此包不分发大模型）。

APK 在 `app/build/outputs/apk/debug/app-debug.apk`。覆盖安装必须沿用原包名和**同一签名**；若签名不同，Android 可能拒绝覆盖。**不要卸载旧版 APP，以免丢失学习记录和已缓存音频。** 更新前备份学习数据。

## 手机测试清单

1. 进入有声书工具，点“开始”，观察计数不断增长；退出工具页、切到其他页面、锁屏 20~30 分钟，通知栏状态应继续增长。
2. 缓存期间打开原著并点播放：页面显示“请先手动暂停”，回缓存页仍显示运行；不因点原著播放自动暂停。
3. 手动点暂停，等待当前合成结束，确认进入“已手动暂停”；再点继续，确认跳过已生成的片段、进度恢复。
4. 缓存期间模拟服务进程回收（并非用户手动强制停止），确认 Android 能尝试重建；返回应用后也会尝试恢复。受系统限制，无法保证任何手机都会立即恢复。
5. 存储不足时应该显示“等待空间”而不是“已手动暂停”；释放空间后自动续接。
6. 查看通知权限、电池限制及手机温度；长期大量合成会耗电、发热，并可能触发系统限制。
